Для более удобной (визуальной) реализации мы заменили заскриптованный код на кастом-теги.

В проект были добавлены кастом-теги для:
1.	Завершения звонка (***HangUp***)
2.	Подсчета реплик noMatch и событий speechNotRecognized (***CounterWithTransition***)

Помимо этого, в проект была добавлена функция в functions.js
```
$global.$ = {
    __noSuchProperty__: function(property) {
        return $jsapi.context()[property];
    }
};
```
для обращения к контектсным переменным таким образом: *$.temp.inRowCounterKeys* вместо *$jsapi.context().temp.inRowCounterKeys*

Для этого в папку *src* была добавлена папка *tags*, которая в свою очередь содержит папки *count* и *hangUp* с необходимыми файлами для кастом-тегов в формате .js и .json. В файлах .js содержатся функции для работы тега, в .json – описание и поля для кастом-тегов.

Код и JGRAPH:
1. Необходимо добавить в нужный стейт кастом-тег. Если у кастом-тега есть обязательные параметры в .json файле нужного тега будет параметр ***required: true***. Пример:
```
{
    "name": "limit",
    "type": "integer",
    "required": true,
    "localization": {
        "ru": "Лимит",
        "eng": "Limit"
    }
}
```
Тогда при вызове кастом-тега необходимо прописать параметры. Из 2 используемых в проекте кастом-тегов обязательные поля есть только у *CounterWithTransition*: inRow = true, limit = 2 (будет считать 3 попадания), targetState = /End (описание полей можно найти в .json файле).
2. Для того, чтобы кастом-теги работали в проекте, в *chatbot.yaml* были добавлены строки:
```
customTags:
  - src/tags/hangUp/hangUp.json
  - src/tags/count/count.json
```
3. При сохранении проекта кастом-теги будут отображаться в нужном блоке в JGRAPH.

Для удобства мы создали отдельный стейт /End для завершения диалога, куда мы переходим из 3 разных стейтов, где раньше разговор заканчивался $dialer.hangUp(). Теперь завершение звонка происходит в одном месте.

***Рекомендация:*** сейчас есть несколько событий (и переходов по событию) *noMatch* в коде, поэтому мы добавили кастом-теги в эти места: они считают попадания в конкретный стейт подряд. Проверьте, что кастом-теги находятся в нужных для идеи проекта местах и Вас устраивает такая логика.
